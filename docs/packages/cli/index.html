@aarusso-nyx/stynx-cli — STYNX workspace CLI for app scaffolding, migrations, doctor, audit, and adoption

@aarusso-nyx/stynx-cli is the STYNX command-line tool for operations an app developer or workspace integrator runs day to day: scaffolding, migrations, health checks, audit-chain validation, privacy exports, and porting support.

Purpose​

Every STYNX-based app needs the same handful of operations: scaffold, migrate, doctor, audit-verify, ROPA-export, and (for the porting use case) adopt-scan. Embedding each as a bash script per app accumulates drift. @aarusso-nyx/stynx-cli consolidates them with a consistent verb shape, JSON-output mode for CI, and the same input-validation discipline as the runtime packages. It's a thin orchestration layer — the heavy lifting lives in the runtime @aarusso-nyx/stynx-* packages it shells into.

You reach for @aarusso-nyx/stynx-cli when you're: bootstrapping a new STYNX app (stynx init), running a migration step in CI or locally, exporting a ROPA before an audit, verifying the audit chain hash, or driving the adopt flow when porting a foreign app's data + endpoints onto STYNX.

What it does NOT do: it does not run inside your app's runtime. It is a developer/operator tool, not a NestJS-injectable. For runtime equivalents (e.g. trigger a migration from app code), use @aarusso-nyx/stynx-data's migration helpers directly.

Audience​

Backend developers + workspace integrators. The init and adopt verbs are for the app-creation moment; the migrate / doctor / audit / privacy verbs are routine app-ops once the app is running.

Install​

pnpm add -D @aarusso-nyx/stynx-cli
# or globally
pnpm add -g @aarusso-nyx/stynx-cli

Then invoke as stynx &lt;verb&gt; (or via pnpm exec stynx &lt;verb&gt; if installed locally).

Peer dependencies: @aarusso-nyx/stynx-core ^1, @aarusso-nyx/stynx-data ^1, @aarusso-nyx/stynx-audit ^1, @aarusso-nyx/stynx-privacy ^1. Node: 24.x.

Quick start​

# Scaffold a new STYNX backend app
npx stynx init my-app

# Or scaffold with Angular workspace files
npx stynx init my-app --angular --dir /workspaces/

# Migrate up to head
stynx migrate up --db postgres://localhost/my_app

# Doctor: app-side health check
stynx doctor

# Verify audit chain integrity (idempotent)
stynx audit verify

# Generate LGPD ROPA
stynx privacy ropa --out ./ropa.json

Public API surface​

CLI verbs​

VerbSubcommand / OptionsDescription
init &lt;app-name&gt;--angular --dir &lt;dir&gt;Scaffold a new STYNX app. Produces a NestJS skeleton with @aarusso-nyx/stynx-* packages pre-installed + a starter AppModule. --angular adds the Angular workspace under packages-web/.
migrate status--db &lt;url&gt;Report applied + pending migrations.
migrate up--db &lt;url&gt; [--to &lt;name&gt;]Apply pending migrations up to head (or to a specific marker).
migrate down--db &lt;url&gt; --to &lt;name&gt;Roll back to a marker.
migrate redo--db &lt;url&gt;Roll back the last migration and re-apply.
doctor--repo-root &lt;path&gt;Run the app-side health check for required paths, package linkage, and build health.
audit verify--db &lt;url&gt;Verify the audit event chain's hash integrity end-to-end. Exits non-zero if a break is found.
privacy ropa--out &lt;path&gt;Generate a LGPD Record-of-Processing-Activities JSON document from the PII column registry.
adopt scan--source &lt;dir&gt; --out &lt;path&gt;Scan a foreign app's controllers + DB schema; emit a structured adoption-plan.
adopt apply--plan &lt;path&gt;Apply a previously-scanned adoption plan to the current STYNX repo.
adopt apply-proposed-permissions--plan &lt;path&gt;Apply the permission proposals from an adoption scan to @aarusso-nyx/stynx-auth config.
adopt link-cognito-users--mapping &lt;path&gt;Link foreign-app user identities to Cognito principals.

Programmatic API​

ExportDescription
buildProgramReturns a Commander.Command with every verb registered. Useful in tests + workspace tooling.
runDoctorProgrammatic doctor entry point (also exported by @aarusso-nyx/stynx-testing).
migrateUp / migrateDown / migrateRedo / migrationStatusDirect migration runners.
verifyAuditChainDirect audit-chain verifier.
generateRopaFromAppDirect ROPA generator.
scaffoldAppDirect scaffolder (init verb's implementation).
adoptScan / adoptApply / adoptApplyProposedPermissions / linkCognitoUsers / formatAdoptScanHumanAdoption flow entry points.

Configuration​

Per-verb flags​

Most verbs accept a --repo-root flag (defaulting to process.cwd()) and a --db &lt;url&gt; flag (defaulting to process.env.DATABASE_URL). Run stynx &lt;verb&gt; --help for the exhaustive list.

Environment variables​

VariableUsed byDescription
DATABASE_URLmigrate, audit verifyDefault DB connection string.
STYNX_AUDIT_CHAIN_HEADaudit verifyOverride the expected chain-head hash for verification.

Examples​

Example 1 — CI migration step​

# .github/workflows/migrate.yml
- name: Apply migrations
  run: pnpm exec stynx migrate up --db ${{ secrets.DATABASE_URL }}

Example 2 — adoption scan + apply​

# Scan a foreign repo
stynx adopt scan --source ../old-app --out ./adoption-plan.json

# Inspect (it's human-readable JSON)
cat adoption-plan.json | jq

# Apply
stynx adopt apply --plan ./adoption-plan.json

Example 3 — programmatic use in workspace tooling​

import { buildProgram } from '@aarusso-nyx/stynx-cli';

const program = buildProgram();
await program.parseAsync(['node', 'stynx', 'migrate', 'status']);

Common pitfalls​

  • Running stynx migrate up against a production DB without dry-run — there is no built-in dry-run gate. Wrap in --db to a staging URL first, OR use stynx migrate status to inspect what would run.
  • stynx audit verify exiting non-zero in CI — the chain hash mismatched. Often caused by replaying audit events out-of-order in a test setup; not necessarily a true integrity break. Inspect the head hash before assuming compromise.

Related packages​

  • @aarusso-nyx/stynx-core — config loading + secret loader the CLI uses to read DATABASE_URL from secrets.
  • @aarusso-nyx/stynx-data — the migration runner the CLI delegates to.
  • @aarusso-nyx/stynx-audit — the audit chain whose integrity audit verify checks.
  • @aarusso-nyx/stynx-privacy — the PII column registry the ROPA generator reads.
  • @aarusso-nyx/stynx-internal-create-stynx-app — a thinner npx-style scaffolder, alternative to stynx init for the very-first-time use case.
